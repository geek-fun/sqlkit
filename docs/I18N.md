# Multi-Language Support Implementation

This document describes the internationalization (i18n) implementation in SQLKit, which supports English, Simplified Chinese, Traditional Chinese (Taiwan), Brazilian Portuguese, Japanese, Korean, and Spanish.

## Overview

The multi-language support is implemented using [vue-i18n](https://vue-i18n.intlify.dev/), following the same pattern as the [dockit project](https://github.com/geek-fun/dockit).

## Structure

### Language Files

All language files are located in `src/lang/`:

- **`index.ts`**: Main i18n configuration, locale detection, and initialization
- **`enUS.ts`**: English (US) translations — the key source of truth
- **`zhCN.ts`**: Chinese Simplified translations
- **`zhTW.ts`**: Traditional Chinese (Taiwan) translations
- **`ptBR.ts`**: Brazilian Portuguese translations
- **`jaJP.ts`**: Japanese translations
- **`koKR.ts`**: Korean translations
- **`esES.ts`**: Spanish translations

### Translation Keys Organization

Translations are organized hierarchically:

```ts
const _translations = {
  common: {
    buttons: { save: 'Save', cancel: 'Cancel' },
    status: { connected: 'Connected', disconnected: 'Disconnected' }
  },
  pages: {
    connections: { title: 'Connections', subtitle: 'Manage your database connections' },
    settings: { title: 'Settings' },
    history: { title: 'History' }
  },
  components: {
    serverForm: { labels: { host: 'Host', port: 'Port' } },
    serverCard: { status: { active: 'Active' } }
  }
}
```

## Language Detection and Storage

The language preference is:

1. **Stored in localStorage** with key `'lang'`
2. **Auto-detection**: If set to `'auto'` (the default), follows the system language (`navigator.language`):
   - `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` → `zhTW`
   - other `zh-*` → `zhCN`
   - `pt-*` → `ptBR`, `ja*` → `jaJP`, `ko*` → `koKR`, `es*` → `esES`
   - anything else → `enUS`

Invalid stored values fall back to auto-detection, and `fallbackLocale` is `enUS`, so a missing key in any locale renders the English string instead of a raw key.

## Usage in Components

### In Vue Components

Import and use the `useI18n` composable:

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
</script>

<template>
  <h1>{{ t('pages.connections.title') }}</h1>
  <p>{{ t('pages.connections.subtitle') }}</p>
</template>
```

### With Interpolation

For dynamic content, use interpolation:

```vue
<template>
  <!-- English: "No connections match your search \"test\"" -->
  <!-- Chinese: "没有匹配\"test\"的连接" -->
  <p>{{ t('pages.connections.empty.message', { query: searchQuery }) }}</p>
</template>
```

## Adding New Translations

To add translations for a new feature:

1. **Add keys to ALL language files in `src/lang/`** — `enUS.ts` first, then the same keys in every other locale file. The parity test (see below) fails the build if a locale file is missing keys.

2. **Use in component**:

```vue
<template>
  <h1>{{ t('pages.myNewPage.title') }}</h1>
</template>
```

## Adding a New Language

1. Copy `src/lang/enUS.ts` to `src/lang/{locale}.ts` (locale codes follow the `zhCN` / `ptBR` style, e.g. `frFR`).
2. Translate the values. Keep brand names, SQL keywords, code identifiers, keyboard key names, and interpolation placeholders (`{name}`) exactly as they are. Keep language-name keys (if any) as native names.
3. Register the file in `src/lang/index.ts`: import it, add the locale code to the `AppLocale` type and `AVAILABLE_LOCALES`, add it to the `messages` object, and extend `detectFromNavigator()` so the system language maps to it.
4. Add the locale to `src/__tests__/i18nParity.test.ts`.
5. Run `npm test` — the parity test and the key-usage test must both pass.

## Testing

- `src/__tests__/i18nParity.test.ts` asserts every locale file carries exactly the `enUS` key set; CI fails on drift, and missing keys fall back to English at runtime rather than showing raw keys.
- `src/__tests__/i18nKeys.test.ts` asserts every literal `t('key')` used in source files resolves in `enUS` and `zhCN`.
- To verify translations manually: run `npm run tauri dev`, switch the system language (or set `localStorage.lang`), and walk through the main pages.

## Implementation Reference

This implementation follows the pattern used in the [dockit project](https://github.com/geek-fun/dockit/blob/master/src/lang/index.ts), using the same `vue-i18n` library and similar configuration.
